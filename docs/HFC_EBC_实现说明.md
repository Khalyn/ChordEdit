# HFC + EBC 实现说明（wjx 分支）

本篇记录 `wjx` 分支上新增的两组模块：**HFC（High-Frequency Completion，高频补全）** 与
**EBC（Edge-Boundary Compositing，边缘轮廓贴合）**，以及把它们落到代码里时得到的实测结论。

---

## 2. 关键发现：所谓"背景"其实并不干净

上游的本地模式用**能量图导出软 mask**（`_energy_mask`），并且为了"不切断弱编辑"做了
`mask ← mask^γ (γ=0.5)` 的抬升。实测（`images/001`）：

```
mask 均值 0.430 | α<0.01 的像素只占 16.5% | α<0.5 占 57.4% | α>0.9 占 14.9%
```

也就是说：**超过一半的像素被判为"背景"，但其中绝大多数仍带着 0.2–0.4 的编辑量**。
后果有两层：

1. 像素融合 `out = α·edit + (1-α)·src` 会把生成结果的模糊漏回背景；
2. 任何"背景复原"模块（含技术报告里的 VRR）都失去前提——因为解码后的背景**并不等于** VAE 还原。

**修复**：在潜空间锚定与像素融合中都使用同一套近二值化 α

```
α' = clamp((α − lo) / w, 0, 1),  lo = 0.30, w = 0.30
```

只做一次（早期版本在潜空间和像素阶段各做一次，导致 α 与真正锚定的区域错位，反而更差）。

## 3. HFC：细节探针（DP）

在 Chord 迁移与 prox 精修之后，用**极低噪声**（`probe_t=0.10`）再前向一次 UNet：

```
z = α_t·x_edit + σ_t·n,   x_probe = (z − σ_t·ε̂(z,t,c_tgt)) / α_t
```

只取高频带做替换，结构/语义仍来自 `x_edit`：

```
g  = clamp((α − (τ−w))/(2w), 0, 1)        # 门控，τ=0.5, w=0.15
lo_e, hi_e = split(x_edit,  σ=1.0)
lo_p, hi_p = split(x_probe, σ=1.0)
x_out = g·(lo_e + s·hi_p) + (1−g)·x_edit
```

`s = 1`（默认）。**能量匹配（`use_energy_match`）实测有害**：DP 是"替换"而非"增益放大"，
用原图同区域能量定标会把新增纹理（胡子、毛皮）拉回原来的光滑水平：

| 配置 | HF_fg |
|---|---|
| +DP，s = 1（默认） | **1.202** |
| +DP，全局能量匹配 | 1.036 |
| +DP，区域能量匹配 | 0.941（比不开 DP 的 1.059 还低） |

因此默认关闭，作为消融项保留（见 `pipeline_chord.py` 注释与论文 §4.4）。

## 4. EBC：边缘轮廓贴合

1. **引导滤波**：以原图亮度为引导，把 64→512 上采样得到的方块状 α 吸附到真实轮廓
   （`edge_radius=8, eps=1e-3`）。
2. **接缝色差补偿**：在 α≈0.5 的接缝带上估计局部 DC 偏移并抵消

```
band  = 4α(1−α)
offset = boxfilter((src − out)·band) / boxfilter(band)
out   += strength · offset · band          # strength = 0.5
```

## 5. 消融结果（8 张示例图，512²，fp16，RTX 3060 Laptop 6 GB）

背景/前景按**上游软 mask 的固定分区**统计（严格背景 α<0.1、严格前景 α>0.9，过渡带单独用
`seam` 衡量），保证各变体在同一批像素上可比。`006` 为全图级编辑（秋→冬），无干净背景，
背景指标不计入均值。

| 变体 | NFE | PSNR_bg↑ | SSIM_bg↑ | HF_bg→1 | HF_fg→1 | lap_var↑ | seam↓ | 耗时 |
|---|---|---|---|---|---|---|---|---|
| upstream | 2 | 50.05 | 0.9979 | 0.944 | 0.996 | 0.00370 | 0.01366 | 0.71 s |
| + 近二值 α | 2 | **56.84** | **0.9997** | 1.003 | 1.059 | 0.00387 | 0.01218 | 0.70 s |
| + EBC | 2 | 56.57 | 0.9997 | 1.002 | 1.059 | 0.00387 | **0.01134** | 0.70 s |
| **+ DP（完整）** | 3 | 56.57 | 0.9997 | 1.002 | **1.202** | 0.00399 | 0.01137 | 0.97 s |
| VRR（报告方案） | 2 | 44.07 | 0.9922 | 1.072 | 1.059 | 0.00387 | 0.01765 | 0.88 s |
| UnsharpMask | 2 | 43.63 | 0.9922 | 1.124 | **1.412** | 0.00796 | 0.01427 | 0.70 s |

要点：

- **近二值 α 是单项最大收益**：PSNR_bg +6.8 dB、SSIM 0.9979→0.9997、HF_bg 回到 1.0。
- **EBC** 把接缝指标压低 17%（0.01366→0.01134），几乎不牺牲背景保真。
- **DP** 把前景细节从 1.059 提到 1.202（+13%），代价 +1 NFE（+0.26 s），背景与接缝不受影响。
- **VRR / UnsharpMask** 都不如完整方法：前者把背景拉回 VAE 瓶颈（第 2 节解释了原因），
  后者过冲到 1.41 且背景 PSNR 掉 7 dB。

复现：

```bat
.venv\Scripts\python.exe scripts\eval_hfc.py --limit 8 --tag final
```

## 6. 已知局限

1. 只有 8 张示例图，**没有 PIE-Bench 全量**，也没有 CLIP-Edited / LPIPS，数字只能说明趋势；
2. 背景分区来自能量 mask，不是人工标注 GT mask；
3. DP 增加 1 NFE；在 6 GB 卡上 `n_samples>1` + DP 会接近显存上限；
4. 全图级编辑（如季节替换）本身没有"干净背景"，背景指标不适用。
